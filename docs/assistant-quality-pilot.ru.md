# Пилот Качества Assistant

Это отдельный инструмент эксперимента, не изменение production Assistant.
Ручной редактор остаётся источником исполняемых правил. Apply в пилоте
компилирует локальный черновик; Save, Publish и запись в CMDB недоступны
транспорту пилота. Legacy-контракты не поддержаны.

## Матрица

| Режим | Вход | Что считается результатом |
| --- | --- | --- |
| `flow` | Описания блоков и параметры, без сохранённых шагов | Все именованные результаты и multiset полных строк |
| `mapping` | Эталонный Object Flow, D2 без применённого mapping | Размещения, карточки, иерархия, направленные рёбра, подписи |
| `end-to-end` | Описания, параметры и D2 | Строки сгенерированного Flow плюс построенная на нём диаграмма |

- A сохраняет инструкции исходного шаблона. B разделяет ответственность
  семантического плана и D2 binding, добавляет короткие предметные факты по
  ID бизнес-блока. Модель обязана подтвердить факт каталогом, а не принимать
  текст за команду. Технический prompt генерации Object Flow не заменяется.
- C отличается от B только дополнительными точными Notes: `binding-result`
  и при необходимости `card-source`, `membership-card-source`,
  `parent-membership-card-source`. Привязки задаются для конкретных мест,
  а не экземпляров карточек, и не перечисляют пары концов ACL.
  В режиме `flow` C не измеряется: это та же генерация данных, что B.
- После первичного сравнения задать `ablations: true` в **новом** manifest.
  `B-prompt-only` убирает предметные факты, `B-knowledge-only` убирает
  новые системные промты. Не изменять holdout по результату предыдущего прогона.
- По умолчанию три повтора; порядок внутри повтора воспроизводим. Таймауты,
  невалидные ответы и пустые диаграммы учитываются в знаменателе.
  Попытки, сорванные бюджетом, остаются в отчёте как `budgetSkipped`,
  но не оцениваются как результаты модели. Затронутые сравнения помечаются
  `incomplete` без прироста качества. Корректный `unresolved` считается отдельно.
  Для необязательных полей ряда сохранять разницу между отсутствием, `null`,
  `false` и `0`. Отсутствующий пустой бизнес-блок не равен известному пустому.

## Воспроизведение

```sh
npm run test:assistant:pilot
node scripts/assistant-quality-pilot.mjs --manifest /path/to/manifest.json
node scripts/assistant-quality-pilot.mjs --manifest /path/to/manifest.json \
  --live --output-dir /path/to/new-private-dir --diagnostics Basic
```

Dry-run не выполняет сетевых запросов и не требует ключей. В manifest:

- `freeze`: `dataHash`, `catalogHash`, `promptHash` (SHA-256 через `hashInput`),
  `model` и неизменяемый `modelRevision`, зафиксированный оператором.
  Для live нужны `isolatedReadOnly: true` и `runtimeConfigHash`. Hash данных,
  каталога и ревизию провайдера фиксирует оператор из изолированного стенда;
  CLI проверяет совпадение модели, runtime-конфигурации и CAS шаблонов
  до/после, но не доказывает иммутабельность внешнего контура самостоятельно.
- `limits`: `maxModelRequests`, `maxRows`, `timeoutMs`, `traversalDepth`;
  необязательно `repeats` на верхнем уровне. `maxModelRequests` ограничивает
  HTTP-запросы к этапам с LLM, а не внутренние вызовы поставщика. Один
  resumable correction на mapping, без автоматического network retry.
- `scenarios`: записи `{id, split, dataKind, modes, inputPath, oraclePath}`.
  `split`: `development|holdout`; `dataKind`: `anonymized|synthetic|private-archive`.
  Пути относительны к manifest. Input: `spec`, опциональные `params`,
  `d2Source`, `authoredD2Source`, `knowledgeByBlock`, `ignoredStaticRoles`;
  для live также `templateRef: {root,templateCode,baseSpecHash}`. Для B
  предметный факт имеет `id`, `kind`, `text`; knowledge не должен содержать
  карточки, эталонные строки, ответы или учётные данные. В C добавлять только
  точные директивы в Notes, не менять структуру D2 или прозу.
- Oracle: `{outcome, expectedStage, blockIds, rows, graph}`. `outcome`: `accepted|unresolved`.
  Для `unresolved` обязателен `expectedStage`: `flow|mapping` либо объект с явным этапом для каждого режима сценария.
  По умолчанию ожидается первая стадия режима: `mapping` для `mapping`,
  `flow` для `flow` и `end-to-end`. Отказ на другой стадии не засчитывается.
  Если `end-to-end` должен завершиться на `mapping`, предыдущие `flow` и
  `rows` должны быть приняты, все строки должны точно совпасть с `rows`
  (включая кратность), а список блоков с `blockIds`, если он задан.
  После `unresolved` последующие стадии не должны выполняться.
  `rows`: `[{blockId,values}]`, включая дубли; `blockIds` перечисляет и пустые
  результаты. `graph`: массивы `placements`, `hierarchy`, `edges`, `labels`.
  Идентичность размещения учитывает карточку, место в шаблоне и родителя, а
  не технический ID рендера. Формат фиксируют `pilotGraphSnapshot` и тесты.
  Для бизнес-приёмки эталон готовится независимо; снимок ранее исполненного
  Spec допустим как контроль регрессии, но не как доказательство замысла.

Live использует только BFF `127.0.0.1:8093` и сессию локального стенда из
`CMDP_PILOT_COOKIE`; не включать её в manifest, shell history или артефакты.
Архив с частными данными блокируется до подключения. В журнале нет промтов,
карточек, ответа модели или cookies. `Basic|Verbose` выводят безопасные
structured события в stderr, по умолчанию `off`. Report хранит стадии, коды,
precision/recall, точные результаты и разницу A/B/C; неизвестные provider
calls/tokens остаются `null`. Для сравнения стоимости нужны метки usage из
того же замороженного провайдера; HTTP calls не подставляются вместо них.

## Результат Калибровки

- На архивных `testtemplate3/4` подготовлены все 48 заданий матрицы; ещё 72
  задания для синтетических holdout. Dry-run: 120, model calls: 0.
- Во верифицированных архивных preview совпали все 13 именованных блоков и
  68 полных строк с кратностью. В каждом снимке 28 размещений, 24 прямые связи
  вложенности и 19 рёбер, включая 3 рёбра легенды; отчёт независимого oracle
  отдельно подтверждает 12 бизнес-карточек, 6 предметных отношений, 16 ACL.
  Из-за `result-row-limit` это совпадение наблюдаемого, не `exact` полного прогона.
- Контроль City/Street/Building даёт 6 точных детерминированных результатов
  на двух снимках в трёх режимах. В трёх контролях без Help ожидаемый отказ
  проверен отдельно. Подмена postal reference на registered меняет строки,
  иерархию и направление к назначению, хотя набор карточек тот же.
- На локальном BFF без LLM: D2-анализ и data-only preview обоих шаблонов
  вернули 200; подготовка семантического контекста вернула 422. В проверках
  наблюдались `semanticPlanContextIncomplete` и `semanticPlanClassUnavailable`.
  Оба шаблона и runtime settings подтверждены неизменными. Повторяемость и
  прирост качества LLM **не измерены**: для этого нужен отдельный замороженный
  обезличенный стенд с полным MCP-контекстом и фиксированной ревизией модели.

Следующий gate: сравнить A/B/C в каждом режиме без лимитов, меняющих эталон;
проверить рост `exact/evaluated` на holdout без роста неверных принятых результатов.
Три повтора отбирают гипотезы, но не обосновывают глобальную замену промтов.
Отдельно перепроверить сценарий в браузере через Apply и Preview, не публикуя
и не перезаписывая исходные шаблоны.
