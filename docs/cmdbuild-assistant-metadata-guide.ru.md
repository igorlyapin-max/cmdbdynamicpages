# Метаданные CMDBuild для Assistant

Assistant разрешает пользовательские термины только по доступному текущей CMDBuild-сессии каталогу. Качество сопоставления повышается не за счёт специальных prompt для конкретного шаблона, а за счёт однозначных метаданных модели.

## Классы

- `Name`: стабильный технический identifier, уникальный в модели.
- `Description`: основное пользовательское название класса.
- `Help`: краткое предметное определение, отличающее класс от похожих классов. Полезно указывать синонимы, но не инструкции по построению конкретного отчёта.
- `Parent`: корректная иерархия нужна для domains, объявленных на superclass.

Пример `Help` для `IS`: `Информационная система; синонимы: ИС, application system. Не является экземпляром Application.`

## Атрибуты

- `Description`: точная подпись из интерфейса, которой пользуются авторы отчётов.
- `Help`: смысл значения, единицы измерения, допустимые варианты и отличие от похожих полей.
- Для boolean явно описывать обе ветви. Пример для `IS.isExt`: `true - внешняя ИС; false - внутренняя ИС.`
- Для IPv4 указывать форму значения: адрес, CIDR-сеть или диапазон. Пример: `IPv4 network in CIDR form, for example 192.168.10.0/24.`
- Для reference указывать целевой объект и рекомендуемое отображаемое поле. Пример: `Ссылка на IpAddress; для сравнения адресов использовать IpAddress.ipAddr.`
- Не помещать в `Help` секреты, персональные данные, runtime identifiers или правила одного отчёта.

## Domains

- Заполнять общее `Description`, а также прямое и обратное описания, если версия CMDBuild их поддерживает.
- Описание должно называть обе стороны и смысл направления. Пример: `ИС использует IP-сеть` / `IP-сеть принадлежит ИС`.
- Cardinality и разрешённые descendants должны соответствовать фактической модели; Assistant проверяет endpoint classes, включая domains superclass.

## Проверка качества

1. Пользовательский термин однозначно совпадает с `Name`, `Description`, alias или предметным `Help`.
2. Reference-путь разрешается до одного terminal attribute на настроенной глубине.
3. Domain имеет читаемые обе стороны и однозначную orientation.
4. Boolean, lookup и IPv4-поля объясняют семантику значений, а не только повторяют название.
5. Проверка выполняется под той же CMDBuild-ролью, что и Designer: недоступные метаданные Assistant использовать не может.
