# Метаданные CMDBuild для Assistant

Assistant разрешает пользовательские термины только по доступному текущей CMDBuild-сессии каталогу. Качество сопоставления повышается не за счёт специальных prompt для конкретного шаблона, а за счёт однозначных метаданных модели.

## Классы

- `Name` (`name` в REST metadata): стабильное техническое имя класса, уникальное в модели; это не атрибут `Code` карточки.
- `Description`: основное пользовательское название класса; для точного сопоставления учитываются и исходное `description`, и перевод `_description_translation`, а не только отображаемый вариант.
- `Help`: краткое предметное определение, отличающее класс от похожих классов. Полезно указывать синонимы, но не инструкции по построению конкретного отчёта.
- `Parent`: корректная иерархия нужна для domains, объявленных на superclass.

Пример `Help` для `IS`: `Информационная система; синонимы: ИС, application system. Не является экземпляром Application.`

Точное техническое имя или точное исходное/переведённое описание имеет приоритет над частичным совпадением описания. Неоднозначные совпадения требуют уточнения; синонимы и `Help` не заменяют подтверждённый identifier.

Сначала подтверждается техническое `name`, даже если в ограниченном каталоге уже есть другой класс с совпадающим Description. Ответ `404` адресной проверки исключает только это техническое имя в текущей сессии, но не поиск по Description. Привязка по Description требует полного доступного каталога и единственного точного совпадения; иначе возвращается причина `descriptionUnverified`, а не совет переименовать существующий класс.

Каталог Assistant ограничен настройками объёма и времени и правами текущей сессии. Отсутствие класса в таком контексте не доказывает отсутствие класса в CMDBuild. Явно указанный технический identifier требует адресной проверки metadata этого класса в тех же правах, даже если он не попал в bounded catalog; такая проверка не обходит allowlist, лимиты или deadline. При неполном каталоге, отказе доступа или недоступной проверке нужно явно сообщать ограничение, а не утверждать, что класс не существует, или молча выбирать частичное совпадение.

Перед вызовом LLM проверяется фактический сериализованный контекст: обязательные классы блоков, поля и явно указанные reference/domain-пути не могут быть вытеснены дополнительными поисковыми кандидатами. Если обязательный контекст не помещается в `assistant.mcp.maxClasses` / `assistant.mcp.maxContextBytes` либо не получен в пределах `assistant.mcp.timeoutMs`, подготовка останавливается с `semanticPlanContextIncomplete`, именами затронутых блоков и точным ограничением. LLM не вызывается; лимиты меняет только оператор. API передаёт локализуемые `feedback.code` и `feedback.params`; интерфейс показывает сообщение на выбранном русском или английском языке.

## Атрибуты

- `Description`: точная подпись из интерфейса, которой пользуются авторы отчётов.
- `Help`: смысл значения, единицы измерения, допустимые варианты и отличие от похожих полей.
- Для boolean явно описывать обе ветви. Пример для `IS.isExt`: `true - внешняя ИС; false - внутренняя ИС.`
- Для IPv4 указывать форму значения: адрес, CIDR-сеть или диапазон. Пример: `IPv4 network in CIDR form, for example 192.168.10.0/24.`
- Для reference указывать целевой объект и рекомендуемое отображаемое поле. Пример: `Ссылка на IpAddress; для сравнения адресов использовать IpAddress.ipAddr.`
- Не помещать в `Help` секреты, персональные данные, runtime identifiers или правила одного отчёта.

## Domains

- Заполнять общее `Description`, а также прямое и обратное описания, если версия CMDBuild их поддерживает.
- Описание должно называть обе стороны и смысл направления. Пример: `ИС использует IP-сеть` / `IP-сеть принадлежит ИС`.
- Cardinality и разрешённые descendants должны соответствовать фактической модели; Assistant проверяет endpoint classes, включая domains superclass.

## Проверка качества

1. Пользовательский термин однозначно совпадает с `Name`, `Description`, alias или предметным `Help`.
2. Reference-путь разрешается до одного terminal attribute на настроенной глубине.
3. Domain имеет читаемые обе стороны и однозначную orientation.
4. Boolean, lookup и IPv4-поля объясняют семантику значений, а не только повторяют название.
5. Проверка выполняется под той же CMDBuild-ролью, что и Designer: недоступные метаданные Assistant использовать не может.
