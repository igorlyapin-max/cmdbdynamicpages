# Агрегация связей D2

Агрегация объединяет уже разрешённые бизнес-связи между теми же визуальными
объектами. Она не меняет выборку Object Flow, правила поиска конечных объектов,
размещение в дереве или визуальную грамматику D2. Runtime не вызывает LLM.

## Настройка

Авторская настройка находится в `relationRules[].aggregation`. Компилятор
переносит её в соответствующий `result.diagrams[].edgeMappings[].aggregation`.
Отсутствие настройки означает, что агрегация выключена:

```json
{
  "enabled": false,
  "groupBy": [],
  "format": "compact",
  "duplicates": "distinct",
  "maxLabelChars": 2000
}
```

| Поле | Значение по умолчанию | Контракт |
| --- | --- | --- |
| `enabled` | `false` | Включение для одного правила, только boolean. |
| `groupBy` | `[]` | Упорядоченные имена полей; не более 32 непустых строк. |
| `format` | `compact` | `compact` или `tree`. |
| `duplicates` | `distinct` | `distinct` или `preserve`. |
| `maxLabelChars` | `2000` | Целое число от 64 до 20000 включительно. |

Все поля необязательны. Неизвестные свойства отклоняются. Предел 32 применяется
к переданному массиву, включая повторяющиеся имена; превышение является ошибкой,
а не основанием обрезать список. Общий лимит request collections не повышает
этот предел. Значения `maxLabelChars` вне допустимых границ также отклоняются.

Текст каждого листа берётся из **существующего `labelTemplate` связи**.
`groupBy` задаёт только уровни группировки; второй label template отсутствует.
Поля выбираются из доступных полей источника связи и проверяются по разрешённому
каталогу. Доступное поле может отсутствовать в прежнем `stage.columns`: его
зависимость должна попасть в проекцию данных. Неизвестное или недоступное поле
нельзя подменять пустым значением для обхода проверки.
Глубокие поля составного результата читаются с сохранённых карточек его
источников. Такая проекция дополняет существующие строки, не размножает их
и не меняет исходную выборку. Для lookup группировка использует исходное
типизированное значение, а подпись группы остаётся человекочитаемой.

## Сетевой Пример

Фрагмент правила для уже настроенных сравнений адресов. Имена полей условные:

```json
{
  "d2ClassKey": "network_access",
  "kind": "connection",
  "mode": "attributeEndpoints",
  "sourceStageId": "selection:networkConnections",
  "sourceField": "SourceAddress",
  "targetField": "TargetAddress",
  "sourceOperator": "ipv4InCidr",
  "targetOperator": "ipv4InCidr",
  "directionPolicy": "dataFields",
  "labelTemplate": "${Port}",
  "aggregation": {
    "enabled": true,
    "groupBy": ["Protocol"],
    "format": "compact",
    "duplicates": "distinct",
    "maxLabelChars": 2000
  }
}
```

Для записей `TCP/443`, `TCP/8443`, `TCP/443` между одной парой визуальных объектов
подпись будет `TCP [443, 8443]`. При `duplicates: preserve` повторяющийся `443`
сохранится, если он принадлежит другой исходной записи.

## Несетевой Пример

Агрегация не привязана к протоколам, адресам или конкретным классам CMDBuild.
Например, зависимости с уже разрешёнными идентификаторами конечных объектов:

```json
{
  "d2ClassKey": "business_dependency",
  "kind": "connection",
  "mode": "deterministicEndpoints",
  "sourceStageId": "selection:dependencies",
  "sourceField": "SourceId",
  "targetField": "TargetId",
  "directionPolicy": "dataFields",
  "labelTemplate": "${Operation}",
  "aggregation": {
    "enabled": true,
    "groupBy": ["Team", "Environment"],
    "format": "tree",
    "duplicates": "preserve",
    "maxLabelChars": 2000
  }
}
```

`Team` и `Environment` образуют два уровня; листья содержат текст `Operation`.
Пустой `groupBy` даёт список листьев без дополнительных уровней. Отсутствующие
значения поля уже извлечённой записи объединяются в группу `Не задано`;
`0` и `false` не считаются отсутствующими. Числовые и строковые значения
не сливаются только из-за одинакового отображаемого текста.

## Границы И Детали

- Объединение выполняется после разрешения endpoint-ов, материализации дерева,
  исключения недопустимых связей и проверки D2 grammar. Не объединяются разные
  visual occurrences, mapping, классы связей, направления или оформления.
- `hierarchyMappings` и статические стрелки D2 template не агрегируются, даже
  если настройка попала в их mapping. Опубликованный static snapshot сохраняет
  уже построенный результат; чтение snapshot не запускает новую агрегацию.
- `distinct` убирает одинаковый текст листьев только внутри одной конечной
  группы. `preserve` сохраняет одинаковый текст разных записей, но не превращает
  несколько matches одной исходной записи в новые бизнес-записи.
  Строки исходного `matchRows` или `joinRows` с разными парами карточек при этом
  считаются разными записями, даже если идентификатор левой карточки совпадает.
- Порядок групп и листьев детерминирован; порядок полей `groupBy` значим.
  Управляющие символы в значениях не должны становиться кодом D2.
- `maxLabelChars` ограничивает видимую подпись, а не размер исходной выборки.
  Скрываются целые значения с маркером `... (+N hidden values)`, а не произвольный
  хвост строки. Маркер входит в лимит. Длина измеряется как длина строки JavaScript.
- Существующий `maxEdges` действует до агрегации. Если вход был ограничен,
  агрегат описывает только обработанную часть, а диагностика отмечает ограничение.
  Агрегация не доказывает полноту выборки и не обходит execution limits.

В структурированных деталях агрегированной связи `data.aggregation` сохраняет
provenance: `memberCount`, `connectionCount`, `members`, дерево `groups`,
`labelTruncated` и `hiddenValues`. `members` содержит `id`, исходную подпись и
структурированные `data` членов агрегата. Удаление повторяющегося текста или
сокращение видимой подписи не удаляет эти сведения. Служебные `runtimeRow` и
`runtimeMapping` не становятся частью публичного результата.

## Сохранение И Preview

Настройки меняются в основном редакторе диаграмм. Выбор полей остаётся query-first:
каталог ищется после непустого запроса, а текущий выбор сохраняется при поиске.
Результат Assistant является предложением; он не сохраняет и не применяет
настройку автоматически. Optional `aggregation` может присутствовать в
`AssistantD2BindingConnection` и в структурном connection context; отсутствие
поля не требует новой версии модели и не должно стирать принятую настройку.

Ручные изменения сохраняются только обычным global `Сохранить` вместе со всем
Spec и историей версии. Отдельного Save/Update endpoint для агрегации нет.
Для изменения этих настроек не требуется повторный LLM-вызов. Mapping identity
учитывает настройку, а dependency projection и mapping input revision учитывают
используемые поля группировки.

Draft preview может показать независимо валидные placements и связи. Если
ошибочна только агрегация, уже подтверждённые стрелки показываются отдельно,
без объединения, с явным предупреждением о причине. Исходная настройка не
изменяется. Ошибка агрегации не должна скрывать корректные узлы и стрелки.
Если исполнимых bindings нет, остаётся source-template preview без данных CMDBuild.
Хранение неполного authoring не означает разрешение на runtime или publication:
строгая execution validation продолжает блокировать невалидную конфигурацию.

Legacy-конфигурация агрегации и второй label template не поддержаны и не запланированы.

## Проверка Контракта

Проверки ниже локальные: не вызывают CMDBuild, Redis, D2 renderer или LLM.

```bash
python3 -B -m unittest discover -s tests/aa -p 'test_edge_aggregation_contract.py'
node scripts/validate-openapi.mjs
```

Тесты AA проверяют схему, а не корректность визуального runtime-результата.
Runtime, preview и сохранение проверяются отдельными сценарными тестами backend/UI.
