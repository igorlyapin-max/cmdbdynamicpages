# Карта регистрации событий

Источник: `scripts/dev-proxy-server.mjs`, call sites `logInfo`, `logWarn`, `logError`, `logDiagnosticBasic`, `logDiagnosticVerbose`, `writeStructuredLog`, `sendSyslog`, `appendBoundedLog`; проверка внешнего маршрута: `scripts/verify-platform-log-route.sh`.

## Каталог

L0/L1 являются ограниченными memory buffers. L2 является основным operational pipeline; L3 опционально дублирует его в direct syslog, L4 описывает доставку stdout/stderr платформой. Для L2 downstream L3/L4 действуют только при настроенном маршруте. Контуры, владельцы, сроки хранения и cadence внешнего сбора: Требует согласования.

## Граница аудита и диагностики

`writeStructuredLog` создает `time`, `level`, `service=cmdbdynamicpages`, `event`; остальные поля добавляются call site. HTTP `requestId` берется из `X-Request-ID` (обрезается до 120 символов) или генерируется UUID; это корреляция, не подтвержденная личность. `sessionHash` сокращает SHA-256 session token до 16 hex-символов; это псевдонимный идентификатор, не доказательство анонимности.

`GET /cmdbuild/custom-api/client-log` и `GET /cmdbuild/custom-api/proxy-log` требуют присутствия CMDBuild cookie. Очистка `clear=1` дополнительно использует `requireStateChangingRequest`. Отдельной проверки роли администратора в этих обработчиках нет. Buffers теряются при restart и не пересылаются целиком в stdout/syslog. Исключение: распознанный client stage `ui-performance` порождает `diagnostic.ui.performance` при включенной диагностике.

История шаблонов сохраняется отдельно в CMDBuild-классе версий, по умолчанию `Cst_QueryTemplateVersion`, с `SpecJson`, автором, временем и комментарием. Это бизнес-данные CMDBuild, не L2 и не гарантия неизменяемого ИБ-аудита. Создание version карточки относится к OAPI115 в [consumed CMDBuild API](openapi/cmdbuild-consumed.openapi.yaml), не к новому logging flow.

## ИБ и незакрытые требования

- Реализованы события CSRF/same-origin/content-type/proxy allowlist, Redis availability, ошибок CMDBuild, CRUD, snapshot publication, D2, Assistant и lifecycle. Не каждый 401/403 upstream имеет самостоятельное предметное audit event.
- Маскирование headers/query основано на конфигурируемых именах. Stage/message client-log только обрезаются; business query values, usernames и свободные exception fields могут сохраняться. `writeStructuredLog` не является универсальным рекурсивным sanitizer.
- `dynamic_ui.render_failed` передает stack без проверки Verbose. Требование выключенных по умолчанию подробных diagnostics с маскированием не выполнено для этой ветки: **P0 blocker runtime-готовности**, не исправлен документацией. Нужны отдельная remediation и focused test; scope текущей задачи только AA.
- Наличие L2 и option L3 не является proof внешнего операционного sink. Пока L3 или L4 не настроен и не подтвержден end-to-end для контура, **P0 blocker эксплуатационной приемки** остается открытым.

См. [схему логирования](logging-flow.md) и [карту секретов](secrets-map.md). Конкретные правила доступа к логам, retention, ИБ-процедуры и маршруты внешней платформы: Требует согласования.
